# 차원문 너머 — 발표 대본

발표자: 김도윤 · 분량 약 5~6분 (시연 제외) · 슬라이드: presentation/deck.html

## <1 PAGE — 타이틀>

반갑습니다.

1팀 차원문 너머의 발표자 김도윤입니다.

저희 팀은 MBTI를 테마로 삼아서 텍스트 기반의 게임을 만들었습니다.

저희가 만든 작품을 간략히 발표토록 하겠습니다. ( 페이지 넘김 )

## <2 PAGE — 아이디어>

여러분은 MBTI 검사를 해보셨나요?

딱딱한 질문지에 반복되는 지루한 설문 내용들, 따분하고 집중력도 떨어지고 — 결과적으로 재미가 없고 힘든 기억으로 저는 남아 있습니다.

해당을 해결하고자 저희는 이 프로젝트에서 RPG 게임으로 MBTI를 검사할 수 있는 쉬운 기회를 자연스럽게 녹여내어 보았습니다. ( 페이지 넘김 )

## <3 PAGE — AWS 기술 스택>

부트캠프에서 배운 다양한 기술 스택을 최대한 사용했으면 좋았겠지만, 저희는 대표적으로 다음의 서비스를 활용하였습니다. 대표적으로 EC2와 Bedrock, S3 등을 사용했습니다. ( 페이지 넘김 )

## <4 PAGE — 아키텍처>

방금 말씀드린 서비스들이 실제로 어떻게 연결되는지 보여드리겠습니다.

저희 아키텍처의 핵심은 슬라이드 제목 그대로 "열린 문은 하나"라는 점입니다. 외부에 공개된 것은 로드밸런서의 80 포트 하나뿐이고, 게임 서버인 EC2는 프라이빗 서브넷에 있어서 퍼블릭 IP 자체가 없습니다. 외부에서 서버나 데이터로 직접 들어올 수 있는 길이 없습니다.

서버가 밖으로 나갈 때는 NAT 게이트웨이라는 한 길로만 나가고, 이 길을 통해 오른쪽의 Bedrock을 호출해서 AI 연출과 지식 검색을 받아옵니다.

그림의 색을 봐주시면 파란색은 코드가 하는 일, 금색은 AI가 하는 일입니다. 점수 계산과 MBTI 판정은 코드가, 스토리 연출은 AI가 — 역할이 구조적으로 분리되어 있습니다. ( 페이지 넘김 )

## <5 PAGE — RAG 파이프라인>

다음은 이번 프로젝트의 핵심 기술인 RAG입니다.

위쪽 줄은 지식을 넣는 과정입니다. 스토리 세계관과 MBTI 조사 자료를 문서로 작성해 S3에 올리면, Knowledge Base가 자동으로 청크를 나누고 임베딩해서 벡터 인덱스를 만들어줍니다.

아래쪽 줄은 게임이 돌아갈 때입니다. 장면에 들어가거나 질문이 들어오면 관련 자료를 벡터 검색으로 찾아 프롬프트에 넣고, Claude가 그 재료로 장면과 답변을 생성합니다.

자료를 추가하고 싶으면 문서를 S3에 올리고 수집 한 번이면 끝입니다. 서버 재시작도, 코드 수정도 필요 없습니다. ( 페이지 넘김 )

## <6 PAGE — 근거 기반 답변>

그래서 뭐가 달라지느냐, 저희가 가장 강조하고 싶은 부분입니다.

그냥 AI에게 MBTI를 물어보면 왼쪽처럼 어디서나 들을 수 있는 일반론이 나옵니다. 저희 게임은 오른쪽처럼 답합니다. "당신은 다리 위 트롤 앞에서 이렇게 했습니다" — 조사된 MBTI 자료와 플레이어가 실제로 한 선택을 인용해서, 근거를 가지고 답합니다.

그리고 게임이니까 하나 더 신경 썼습니다. 정해진 스토리를 매번 똑같이 트는 게 아니라, 검색에 선택 이력을 섞어 장면과 선택지를 매번 새로 생성합니다. F5로 새로고침만 해도 도입부부터 달라지는 걸 확인하실 수 있습니다.

창의성은 temperature 0.7로 조율했습니다. 너무 창의적이면 JSON 응답이 깨져 게임이 멈출 수 있어서, 스키마 검증과 폴백까지 넣어 적당히 창의적이면서도 안정적으로 돌아가게 만들었습니다. ( 페이지 넘김 )

## <7 PAGE — 게임 플로우>

게임 진행은 간단합니다. 용사로 소환되면서 시작해, 여덟 번 선택하면 판정이 나옵니다.

분기는 일상 4개, 전투 4개입니다. 일상 선택은 1점, 전투 선택은 2점을 주는데 — 평온할 때보다 위기 상황의 선택이 본성을 더 강하게 드러낸다고 봤기 때문입니다.

이렇게 하면 축마다 합계가 3점, 홀수라서 동점이 구조적으로 나올 수 없습니다. 판정은 항상 확정되고, 이 계산에 AI는 전혀 관여하지 않습니다. ( 페이지 넘김 )

## <8 PAGE — AI 에이전트 호출>

그럼 AI는 언제, 어떻게 부르느냐 — 단계마다 다릅니다.

게임 시작과 선택 제출 때는 '게임 마스터' 프롬프트가 지식베이스를 검색해 장면과 선택지를 만듭니다. 여덟 번째 선택 직후에는 먼저 코드가 MBTI를 판정하고, 그다음 '분석가' 프롬프트가 선택 기록을 인용해 결과지를 씁니다. 마지막 자유 질문에는 '상담 챗봇' 프롬프트가 지식베이스 근거로만 답합니다.

표의 왼쪽 파란 열이 코드, 오른쪽 금색 열이 AI입니다. 규칙과 판정은 코드, 검색과 생성은 AI — 이 경계선 덕분에 AI 호출이 실패해도 게임은 죽지 않고 고정 스토리로 이어집니다. ( 페이지 넘김 )
