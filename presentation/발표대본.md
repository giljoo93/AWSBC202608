## <2 — 아이디어>

여러분은 MBTI 검사를 해보셨나요?

딱딱한 질문지에 반복되는 지루한 설문 내용들, 따분하고 집중력도 떨어지고 — 결과적으로 재미가 없고 힘든 기억으로 저는 남아 있습니다.

해당을 해결하고자 저희는 이 프로젝트에서 RPG 게임으로 MBTI를 검사할 수 있는 쉬운 기회를 자연스럽게 녹여내어 보았습니다. ( 페이지 넘김 )

## <3 — AWS 기술 스택>

부트캠프에서 배운 다양한 기술 스택을 최대한 사용했으면 좋았겠지만, 저희는 대표적으로 다음의 서비스를 활용하였습니다. 대표적으로 EC2와 Bedrock, S3 등을 사용했습니다. ( 페이지 넘김 )

## <4 — 아키텍처> — 핵심: "문은 하나만 열어놨다"

그림이 복잡해 보이는데, 핵심은 딱 하나입니다. 문을 하나만 열어놨다는 거예요.

손님은 정문으로만 들어오고, 게임 서버는 안쪽 방에 숨겨놨습니다. 그래서 밖에서는 서버도, 데이터도 직접 못 건드립니다. ( 페이지 넘김 )

## <5 — RAG> — 핵심: "AI에게 교과서를 쥐여줬다"

저희는 AI한테 그냥 물어보지 않았습니다. 먼저 교과서를 만들어줬어요.

스토리 설정집이랑 MBTI 조사 자료를 올려두면, AI가 필요할 때마다 찾아 읽고 이야기를 만듭니다. 자료만 갈아끼우면 게임 내용도 바뀝니다. ( 페이지 넘김 )

## <6 — 근거 기반 답변> — 핵심: "아무 말이나 안 하고, 근거를 대고 말한다"

그래서 답이 다릅니다.

보통 AI는 "이 유형은 원래 이렇대요" 하고 일반론을 말하는데, 저희 게임은 "당신, 아까 이렇게 선택하셨잖아요"라고 내 행동을 근거로 말해줍니다.

스토리도 매번 새로 만들어져서, 새로고침만 해도 다른 이야기가 나옵니다. ( 페이지 넘김 )

## <7 — 게임 플로우> — 핵심: "여덟 번 고르면 끝, 무승부 없음"

게임 방법은 간단합니다. 여덟 번만 고르면 돼요.

평소 상황 네 번, 위기 상황 네 번인데 — 위기 때 선택에 점수를 두 배 줬습니다. 급할 때 진짜 성격이 나오니까요.

이 설계 덕분에 비기는 경우가 아예 없습니다. ( 페이지 넘김 )

## <8 — AI 역할 분담> — 핵심: "점수는 계산기가, 이야기는 작가가"

역할을 딱 나눴습니다.

점수와 판정은 계산기처럼 정확한 코드가 하고, 이야기와 해설은 AI 작가가 씁니다.

그래서 AI가 실수해도 결과는 안 틀어지고, 게임도 안 멈춥니다. ( 페이지 넘김 )
