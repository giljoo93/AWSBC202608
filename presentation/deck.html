01아이디어

검사지를 덮고, 이야기 속으로

설문형 MBTI 검사는 "나는 이런 사람"이라는 자기보고에 의존합니다. 우리는 질문 대신 상황을 주고, 이야기 속 실제 선택으로 성향을 읽습니다.

기존 방식
"당신은 모임에서 먼저 말을 거는 편입니까?"

서사

설문 대신 스토리

프롤로그부터 엔딩까지 하나의 판타지 서사. 선택 8번이면 검사가 끝납니다.

정확도

위기가 본성을 드러낸다

일상 분기보다 전투 분기 선택에 2배 가중치 — 고압 상황의 선택이 성향을 더 강하게 반영합니다.

AI 게임 마스터

연출·결과지·상담까지

점수 규칙

일상 +1 · 전투 +2

선택마다 해당 속성(E/I·S/N·T/F·J/P)에 가점. 근거 문장이 함께 기록되어 결과지의 인용 재료가 됩니다.

축 설계

축당 2회 = 합계 3점

4개 축 × (일상 1점 + 전투 2점). 축 합계가 홀수라 동점이 구조적으로 불가능 — 판정이 항상 확정됩니다.

판정

E>I → E, 4글자 조합

축별 우세 속성을 이어 붙여 16타입 확정. 이 계산에 LLM은 관여하지 않습니다.

06설계 원칙

점수는 코드가, 서사는 모델이

신뢰성

LLM은 판정에 손대지 못한다

점수 규칙은 storyboard 데이터에 정적 정의, 합산·판정은 엔진 코드. 모델 출력이 점수에 닿는 경로 자체가 없습니다.

보안

액세스 키 0개

EC2 IAM role이 자격증명을 공급하고 권한은 InvokeModel·Retrieve로 최소화. 서버는 프라이빗 서브넷 — 공개된 건 ALB의 80뿐입니다.

개발 경험

stub 모드

GAME_LLM=stub 하나로 AWS 없이 완주 테스트 — 비용 0원으로 로컬 개발, 배포 시 bedrock으로 전환.

안정성

실패해도 게임은 죽지 않는다

KB 검색·장면 생성이 실패하면 자동으로 고정 스토리로 폴백. RAG가 꺼져 있어도 완주가 보장되는 구조입니다.

협업

JSON 계약서 하나로 분업

API.md에 요청·응답 폼을 전부 명세. 프론트는 목 데이터로, 백엔드는 stub으로 — 서로를 기다리지 않고 개발했습니다.

범위 관리

의도된 단순함

세션은 서버 인메모리, DB 없음. 부트캠프 범위에 맞춘 선택이고, 필요해지는 시점과 확장 경로(S3 덤프)를 문서에 남겼습니다.

07프론트엔드

비주얼 노벨의 문법으로

챗 UI가 아니라 게임 화면처럼 — 텍스트 게임 레퍼런스를 조사해 서술과 대사를 나누는 비주얼 노벨 관례를 따랐습니다.

연출

장면이 살아 있다

서술(어두운 패널)과 대사(금빛 패널, 화자 명찰) 분리 · 배경 크로스페이드 · 등장인물 입상 · 장 전환 타이틀 카드 · 판정 연출 "차원문이 당신을 읽고 있습니다"

아트

이미지 16장, 전부 생성형

배경 10장 + 인물 6명 — Bedrock 이미지 모델에 구도 스케치를 넣어 제작. 파일이 없으면 그라디언트·실루엣으로 자동 폴백해 깨지지 않습니다.

구조

플래그 하나로 목 ↔ 실서버

USE_MOCK 한 줄만 바꾸면 백엔드 연결. 목과 실서버가 같은 JSON 계약을 지키므로 렌더링 코드는 그대로입니다.

품질

브라우저 없이 완주 테스트

jsdom 헤드리스 테스트가 8분기를 실제로 클릭해 판정·백로그까지 검증. 접근성으로 키보드 선택과 모션 감소 설정도 지원합니다.

시나리오

소환 → 선택 8번 → 판정 → Q&A

프롤로그에서 시작해 일상·전투 분기를 지나면 판정 연출과 함께 MBTI 카드가 나타나고, "INTJ랑 잘 맞아?" 같은 자유 질문에 챗봇이 답합니다. KB 동적 생성 덕에 같은 분기도 매 플레이 문장이 달라집니다.

주목할 점

결과지가 내 선택을 인용한다

"당신은 다리 위 트롤 앞에서 ~했습니다"처럼 실제 선택 문장이 근거로 등장하고, 일상과 전투에서 선택이 갈린 축은 "평소에는 ~지만 위기에는 ~"으로 짚어줍니다.
