살아있는 스토리

새로고침만 해도 다른 이야기

KB 검색 쿼리에 선택 이력을 섞어 장면·선택지 문구를 매번 새로 생성 — 정형화된 고정 스토리가 아니라, F5로 다시 들어가도 도입부부터 다르고 선택에 따라 전개가 달라집니다.

구조화된 창의성

temperature 0.7의 균형

너무 창의적이면 JSON 응답 구조가 깨질 수 있어 온도를 0.7로 조율 — 스키마 검증을 통과하는 안정성과 적당히 창의적인 스토리 진행을 동시에 잡았고, 생성 실패 시 고정 스토리로 폴백합니다.

점수 규칙

일상 +1 · 전투 +2

선택마다 해당 속성(E/I·S/N·T/F·J/P)에 가점. 근거 문장이 함께 기록되어 결과지의 인용 재료가 됩니다.

축 설계

축당 2회 = 합계 3점

4개 축 × (일상 1점 + 전투 2점). 축 합계가 홀수라 동점이 구조적으로 불가능 — 판정이 항상 확정됩니다.

판정

E>I → E, 4글자 조합

축별 우세 속성을 이어 붙여 16타입 확정. 이 계산에 LLM은 관여하지 않습니다.

선택 이력을 섞어 KB 재검색 → 다음 장면·선택지 문구 생성 (JSON 검증)
8번째 선택 직후자동

분석가 프롬프트 — 선택 기록 인용 + mbti KB 근거로 결과지 작성

모든 호출은 Converse API · temperature 0.7 · 실패 시 고정 스토리 폴백 — AI가 실패해도 게임은 죽지 않는다
