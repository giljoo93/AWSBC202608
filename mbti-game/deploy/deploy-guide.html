준비 — 리전 고정과 코드 압축

⏱ 10분

0-1. 리전을 us-east-1로 고정

AWS 콘솔에 로그인한 뒤, 화면 오른쪽 위의 리전 이름을 눌러 미국 동부(버지니아 북부) us-east-1을 선택하세요.

⚠ 가장 흔한 사고오늘 만드는 모든 것(IAM 제외)은 이 리전 안에 있어야 서로를 찾을 수 있습니다. 화면이 갑자기 "아무것도 없음"으로 보이면 십중팔구 리전이 바뀐 것이니 먼저 오른쪽 위부터 확인하세요.

0-2. 코드 압축(zip) 만들기

내 컴퓨터에서 mbti-game 폴더 자체를 마우스 오른쪽 클릭 → 압축(ZIP) 파일로 보내기 (또는 "압축") → mbti-game.zip이 생기면 성공.

⚠ 폴더째 압축하세요폴더를 열고 안의 파일들만 선택해서 압축하면 서버에서 폴더 이름이 사라져 이후 명령이 어긋납니다. 반드시 mbti-game 폴더 자체를 압축하세요. __pycache__ 폴더는 들어가도 무해합니다.

IAM 역할 만들기

⏱ 10분

IAM 역할은 EC2 서버에게 쥐여주는 출입증입니다. 이 출입증 덕분에 서버 안에 비밀번호나 키 파일을 하나도 저장하지 않고 Bedrock과 S3를 쓸 수 있습니다.

콘솔 검색창에 IAM 입력 → 역할(Roles) → 역할 생성

차례대로 이렇게 고릅니다.

화면선택할 것
신뢰할 수 있는 엔터티 유형AWS 서비스
사용 사례 (서비스)EC2 선택 → 다음
권한 정책 (검색해서 체크 3개)AmazonBedrockLimitedAccess
AmazonSSMManagedInstanceCore
AmazonS3ReadOnlyAccess
역할 이름mbti-game-ec2-role

세 정책의 뜻: Bedrock 호출 허용 / 브라우저 터미널(Session Manager) 접속 허용 / S3에서 코드 zip 내려받기 허용.

✔ 확인 포인트역할 목록에 mbti-game-ec2-role이 보이면 성공. 액세스 키는 절대 발급하지 않습니다 — 이 프로젝트는 키 없이 돌아가도록 만들어져 있습니다.

Bedrock 모델 켜기

⏱ 5분

Bedrock의 모델은 처음엔 꺼져 있어서, 쓰고 싶은 모델을 콘솔에서 한 번 켜야 합니다.

콘솔 검색창에 Bedrock 입력 → 왼쪽 메뉴 맨 아래 모델 액세스(Model access) → 모델 액세스 수정

Anthropic Claude 계열 모델 하나를 체크하고 저장하세요 (교육 계정은 보통 즉시 "액세스 부여됨"으로 바뀝니다). 그다음이 중요합니다:

⚠ 모델 ID를 복사해 메모장에 붙여두세요모델 이름을 클릭하면 상세 화면에 모델 ID가 있습니다 (형식 예: anthropic.claude-…). 5단계에서 이 값을 딱 한 번 붙여넣게 됩니다. 화면에 보이는 값을 그대로 복사하세요 — 예시를 손으로 따라 치면 오타가 납니다.

S3 버킷 — 코드와 웹 화면 올리기

⏱ 10분

버킷 하나를 두 용도로 씁니다: ① 게임 화면 파일(index.html) 보관 — 나중에 CloudFront가 여기서 꺼내 보여줌, ② 코드 zip 전달 — EC2가 여기서 내려받음.

콘솔 검색창에 S3 입력 → 버킷 만들기
항목값
버킷 이름내이름-mbti-game 처럼 전 세계에서 유일한 이름 (소문자·숫자·하이픈만)
퍼블릭 액세스 차단모두 차단 유지 (기본값 그대로 — 절대 풀지 마세요, CloudFront가 대신 열어줍니다)
나머지전부 기본값 → 버킷 만들기

만든 버킷을 클릭해 파일 2개를 올립니다 (업로드 버튼 → 파일 끌어다 놓기):

  • mbti-game\frontend\index.html — 버킷 맨 위(루트)에 그대로
  • mbti-game.zip — 이것도 루트에 그대로
✔ 확인 포인트버킷 객체 목록에 index.html과 mbti-game.zip 두 줄이 보이면 성공.

EC2 서버 만들기

⏱ 15분
콘솔 검색창에 EC2 입력 → 인스턴스 시작(Launch instance)
항목값
이름mbti-game-server
AMI (운영체제)Amazon Linux 2023 (기본 선택)
인스턴스 유형t3.micro (프리티어)
키 페어키 페어 없이 계속 진행 — 브라우저 터미널로 접속하므로 필요 없음
네트워크 설정기본 VPC 그대로. 퍼블릭 IP 자동 할당: 활성화 확인
보안 그룹 (방화벽)새로 생성 → 규칙 추가: 유형 사용자 지정 TCP, 포트 8000, 소스 0.0.0.0/0 (Anywhere)
고급 세부 정보 ▾ 열기IAM 인스턴스 프로파일 = mbti-game-ec2-role ← 1단계의 출입증을 여기서 끼웁니다. 잊기 쉬운 지점!
⚠ 8000 포트를 전체 공개(0.0.0.0/0)로 여는 이유CloudFront가 서버에 접속해 오기 때문입니다. 실습을 단순하게 하려는 설정이며, 실습이 끝나면 9단계에서 서버째 정리합니다. (더 좁히고 싶다면 소스에서 관리형 접두사 목록 com.amazonaws.global.cloudfront.origin-facing을 선택하면 CloudFront만 허용됩니다.)

인스턴스 시작을 누르고, 목록에서 상태가 실행 중(Running)이 될 때까지 1~2분 기다립니다. 그리고 인스턴스를 클릭해 퍼블릭 IPv4 DNS (예: ec2-3-92-….compute-1.amazonaws.com)를 메모장에 복사해 두세요 — 6단계에서 씁니다.

서버 설치 — 복사–붙여넣기 5줄

⏱ 15분

서버에 접속할 때 브라우저 터미널을 씁니다. 프로그램 설치도, 키 파일도 필요 없습니다.

EC2 → 인스턴스 선택 → 연결(Connect) 버튼 → Session Manager 탭 → 연결

검은 화면(터미널)이 열리면 성공. 아래 블록을 순서대로 복사해 터미널에 붙여넣고 Enter 하세요. 주황색 부분 2곳만 메모장에 적어둔 내 값으로 바꿉니다.

① 작업 계정으로 전환 (Session Manager는 다른 계정으로 시작되므로 꼭 먼저):

sudo su - ec2-user

② 코드 내려받고 풀기 — 버킷이름을 3단계의 버킷 이름으로:

aws s3 cp s3://버킷이름/mbti-game.zip . sudo dnf install -y unzip unzip -o mbti-game.zip

③ 모델 ID 끼워넣기 — 모델ID를 2단계에서 복사한 값으로 (따옴표는 지우지 마세요):

sed -i "s|CHANGE_ME|모델ID|" mbti-game/deploy/gamesvc.service

④ 설치 실행 — 파이썬 설치부터 서버 등록·가동까지 자동:

bash mbti-game/deploy/setup-ec2.sh

⑤ 동작 확인:

curl http://localhost:8000/health
✔ 확인 포인트{"ok":true,"llm":"bedrock"} 가 출력되면 서버 완성입니다. 서버가 꺼지거나 재부팅돼도 자동으로 다시 켜지도록 등록까지 끝난 상태입니다.
⚠ 붙여넣기가 안 될 때브라우저 터미널에서는 Ctrl+Shift+V 또는 마우스 오른쪽 클릭 → 붙여넣기를 사용하세요.

CloudFront — 하나의 주소로 묶기

⏱ 20분 · 가장 헷갈리는 단계

CloudFront 배포 하나에 문(오리진)을 두 개 답니다: 기본 문은 S3(게임 화면), 두 번째 문은 EC2(백엔드). 그리고 "주소가 /api/로 시작하면 EC2 문으로 보내라"는 규칙(동작/Behavior)을 추가합니다.

6-1. 배포 생성 (S3 문 달기)

콘솔 검색창에 CloudFront 입력 → 배포 생성
항목값
Origin domain목록에서 내 S3 버킷 선택
원본 액세스 (Origin access)원본 액세스 제어 설정(OAC) 선택 → 새 OAC 생성 → 기본값으로 생성
웹 애플리케이션 방화벽(WAF)보안 보호 비활성화 (실습용)
기본 루트 객체 (Default root object)index.html ← 설정 섹션 맨 아래에 있음, 꼭 입력
⚠ 배포 생성 직후 파란 안내 배너가 뜹니다"S3 버킷 정책을 업데이트해야 합니다" — 정책 복사 버튼 클릭 → 배너의 링크로 S3 권한 화면 이동 → 버킷 정책 편집에 붙여넣고 저장. 이걸 빼먹으면 나중에 AccessDenied가 나옵니다.

6-2. EC2 문 달기 (오리진 추가)

방금 만든 배포 클릭 → 원본(Origins) 탭 → 원본 생성
항목값
Origin domain4단계에서 메모한 EC2 퍼블릭 IPv4 DNS 붙여넣기
프로토콜HTTP만(HTTP only) ← 제일 많이 틀리는 곳! HTTPS로 두면 502 오류
HTTP 포트8000

6-3. /api/* 규칙 추가 (동작 생성)

같은 배포 → 동작(Behaviors) 탭 → 동작 생성
항목값
경로 패턴 (Path pattern)/api/*
원본 (Origin)방금 만든 EC2 오리진 선택
허용된 HTTP 방법GET, HEAD, OPTIONS, PUT, POST, PATCH, DELETE (맨 아래 전체 옵션 — POST가 꼭 포함돼야 게임이 돌아갑니다)
캐시 정책CachingDisabled
원본 요청 정책 (Origin request policy)AllViewerExceptHostHeader

저장 후 배포 상태가 배포됨(Deployed)이 될 때까지 5~10분 걸립니다. 이 시간에 커피 한 잔 ☕

최종 확인과 문제 해결

⏱ 10분

배포 상세 화면의 배포 도메인 이름 (예: d1a2b3c4.cloudfront.net)을 브라우저 새 탭에 붙여넣으세요. 게임 시작 화면이 뜨고 → 8개 분기를 완주하면 → MBTI 카드와 결과지가 나오고 → 질문까지 되면 배포 완료 🎉

안 될 때 — 증상별 처방전

증상원인과 처방
첫 화면부터 AccessDenied6-1의 버킷 정책을 안 붙였거나, 기본 루트 객체가 비어 있음
화면은 뜨는데 시작 버튼에서 502/504EC2 오리진 프로토콜이 HTTPS로 되어 있음(→ HTTP만으로), 또는 보안 그룹 8000 규칙 누락
시작 버튼에서 403/api/* 동작의 허용 방법에 POST 누락
게임은 되는데 결과지에서 오류Bedrock 문제. 서버 터미널에서 sudo journalctl -u gamesvc -n 50 실행 → 모델 ID 오타, 모델 액세스 미활성화, IAM 정책 누락 중 하나
로그에 "on-demand throughput isn't supported"이 모델은 추론 프로파일로 불러야 함 → 5단계 ③을 모델 ID 앞에 us.를 붙인 값(예: us.anthropic.…)으로 다시 실행 후 sudo systemctl restart gamesvc
아까는 됐는데 게임이 초기화됨정상입니다 — 점수는 서버 메모리에만 있어서 서버 재시작 시 사라집니다. "다시 시작"하면 됩니다

서버 쪽을 고친 뒤에는 터미널에서 sudo systemctl restart gamesvc 한 줄로 재시작할 수 있습니다.
