S3 벡터 데이터베이스로 게임에 RAG 붙이기

스토리 문서와 MBTI 자료를 S3에 올리고, Bedrock Knowledge Base로 벡터 데이터베이스를 만들어 게임에 연결하는 전체 과정. AWS 콘솔에서 클릭으로 진행하며, 코드는 이미 준비되어 있으니 마지막에 환경 변수 두 줄만 넣으면 됩니다.

먼저: RAG가 뭔가요?

RAG(검색 증강 생성)는 "AI에게 답하기 전에 자료를 찾아 읽게 하는 것"입니다.

  1. 문서를 잘게 쪼개서(청크) 각 조각을 숫자 목록(벡터)으로 바꿔 저장합니다 — 이 변환을 임베딩이라 합니다.
  2. 질문이 들어오면 질문도 벡터로 바꿔, 의미가 가까운 조각을 찾아냅니다. 단어가 달라도 뜻이 비슷하면 찾아집니다.
  3. 찾은 조각을 AI에게 "이 자료를 근거로 답해"라고 건네줍니다.

AWS에서는 이 전체 과정을 Bedrock Knowledge Base가 대신해 줍니다. 우리는 S3에 문서를 올리고 버튼 몇 개만 누르면 됩니다.

1S3 버킷 만들기

  1. AWS 콘솔 접속 → 오른쪽 위 리전이 버지니아 북부(us-east-1)인지 확인 (EC2·Bedrock과 같은 리전이어야 합니다).
  2. 검색창에 S3 입력 → 버킷 만들기(Create bucket) 클릭.
  3. 버킷 이름: mbti-game-kb-이름이니셜 (전 세계에서 유일해야 하므로 이니셜·숫자를 붙이세요).
  4. 나머지는 전부 기본값 그대로 → 버킷 만들기.

2문서 업로드

프로젝트의 mbti-game/kb/ 폴더에 업로드용 문서가 준비되어 있습니다.

  1. 방금 만든 버킷 클릭 → 업로드(Upload) → 폴더 추가(Add folder) → 컴퓨터의 kb/story 폴더 선택 → 업로드.
  2. 같은 방법으로 kb/mbti 폴더도 업로드.
  3. 업로드가 끝나면 버킷 안에 story/와 mbti/ 두 폴더가 보여야 합니다.
팀원 MBTI 자료 팀원이 가진 MBTI 자료(PDF·Word·텍스트 모두 가능)는 kb/mbti 폴더에 복사한 뒤 같은 방법으로 mbti/에 업로드하면 됩니다. 나중에 추가해도 되고, 추가할 때마다 6단계의 Sync만 다시 누르면 반영됩니다.

3Bedrock 모델 액세스 확인

  1. 검색창에 Bedrock 입력 → 왼쪽 메뉴 맨 아래 모델 액세스(Model access).
  2. 다음 두 가지가 액세스 허용됨 상태인지 확인, 아니면 요청:
    • 텍스트 생성 모델 — 기존 배포에서 쓰던 모델 (예: Claude 계열)
    • Titan Text Embeddings V2 — 문서를 벡터로 바꾸는 임베딩 모델. 이번에 새로 필요합니다.

4Knowledge Base 만들기 — 스토리용

  1. Bedrock 왼쪽 메뉴 → Knowledge Bases → 지식 기반 생성(Create knowledge base) → Knowledge Base with vector store 선택.
  2. 이름: mbti-game-story-kb. IAM 권한은 새 서비스 역할 생성(기본값) 그대로.
  3. 데이터 소스: Amazon S3 → 내 버킷 선택 → 접두사(Prefix)에 story/ 입력 — 스토리 문서만 이 KB에 들어가게 하는 설정입니다.
  4. 임베딩 모델: Titan Text Embeddings V2.
  5. 벡터 스토어: Amazon S3 Vectors 선택 — 실습에 가장 저렴하고 관리가 필요 없습니다.
  6. 생성 클릭 → 완료되면 데이터 소스 화면에서 동기화(Sync) 클릭 → 상태가 완료될 때까지 대기(수 분).
  7. KB 상세 화면 상단의 지식 기반 ID(Knowledge base ID)(10자리 영숫자, 예: ABCDE12345)를 메모하세요. → 이것이 GAME_KB_STORY 값.

5Knowledge Base 만들기 — MBTI용

4단계를 한 번 더, 값만 바꿔서:

  1. 이름: mbti-game-mbti-kb, 접두사: mbti/, 나머지는 동일.
  2. 생성 → Sync → 지식 기반 ID 메모 → 이것이 GAME_KB_MBTI 값.

6EC2에 검색 권한 주기

게임 서버(EC2)가 KB를 검색할 수 있도록 권한 한 개를 추가합니다.

  1. 콘솔 검색창에 IAM → 왼쪽 역할(Roles) → 기존 배포 때 EC2에 붙인 역할 클릭.
  2. 권한 추가(Add permissions) → 인라인 정책 생성(Create inline policy) → JSON 탭 → 아래 내용 붙여넣기:
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": ["bedrock:Retrieve"],
      "Resource": "arn:aws:bedrock:us-east-1:*:knowledge-base/*"
    }
  ]
}
  1. 정책 이름: kb-retrieve → 정책 생성.

7새 코드 올리고 환경 변수 설정

  1. 수정된 mbti-game 폴더를 기존 배포 때 쓴 방법 그대로 EC2의 /home/ec2-user/mbti-game에 덮어써 올립니다.
  2. EC2에 접속해 서비스 설정 파일을 엽니다: sudo nano /etc/systemd/system/gamesvc.service
  3. 메모해 둔 KB ID 두 개를 채웁니다:
Environment=GAME_KB_STORY=여기에_스토리_KB_ID
Environment=GAME_KB_MBTI=여기에_MBTI_KB_ID
  1. 저장 후 서비스 재시작:
sudo systemctl daemon-reload
sudo systemctl restart gamesvc

8동작 확인

  1. 브라우저에서 내주소/health 접속 → 아래처럼 나오면 성공:
{"ok": true, "llm": "bedrock", "kb_story": true, "kb_mbti": true}
  1. 다양성 확인: 게임을 두 번 플레이 → 같은 장면이라도 내레이션과 선택지 문구가 다르게 나옵니다. 선택을 다르게 하면 다음 장면의 내용도 조금씩 달라집니다.
  2. Q&A 확인: 게임을 끝까지 플레이 → 챗봇에게 팀원 자료에만 있는 내용을 질문 → 자료 기반으로 답하면 성공.
바뀌어도 안 바뀌는 것 장면과 선택지 문구는 매번 새로 생성되지만, 어떤 선택이 어떤 MBTI 성향에 몇 점인지는 코드에 고정되어 있습니다. AI가 아무리 다르게 써도 판정의 공정성은 유지됩니다.

문제 해결

증상원인과 해결
/health에 kb_story: false 환경 변수가 비어 있음. 7단계의 서비스 파일에서 ID 확인 후 daemon-reload + restart.
장면이 항상 똑같음 /health의 llm이 stub이면 Bedrock 미사용 상태. 서비스 파일의 GAME_LLM=bedrock과 GAME_BEDROCK_MODEL 확인.
서버 로그에 [rag] KB 검색 실패 6단계 IAM 권한 누락이 대부분. KB ID 오타, 리전 불일치도 확인. 실패해도 게임은 고정 스토리로 계속 동작합니다. 로그 보기: sudo journalctl -u gamesvc -f
Sync가 실패하거나 0건 처리 데이터 소스의 접두사(story/, mbti/)와 실제 업로드된 폴더 이름이 일치하는지 확인.
챗봇이 팀원 자료를 모른다고 답함 자료 업로드 후 Sync를 다시 눌렀는지 확인. Sync 없이는 새 자료가 벡터로 변환되지 않습니다.
비용 메모 S3 Vectors는 저장·검색 모두 실습 규모에서는 매우 저렴합니다. 임베딩 비용은 Sync할 때 문서량만큼 한 번씩만 발생합니다. 다만 동적 장면 생성으로 플레이 1회당 Bedrock 텍스트 생성 호출이 약 9회(장면 8 + 결과지 1) 발생하니, 실습이 끝나면 EC2 중지를 잊지 마세요.

자료를 계속 키우는 법

  1. 팀원 자료를 kb/mbti에 추가 (형식 자유: md·pdf·docx·txt).
  2. S3 버킷의 mbti/에 업로드.
  3. Knowledge Base에서 Sync 클릭 — 끝. 서버 재시작도 필요 없습니다.
